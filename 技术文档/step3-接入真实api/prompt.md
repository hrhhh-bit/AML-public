## 3. 核心改造与实施目标（对标阶段 1 规划 1.1 ~ 1.5）

### 目标 A：实现高可用 OpenAI 兼容 LLM 适配器（满足 1.1 与 1.5 要求）

在 `aml_agent/` 下实现或完善客户端适配模块（例如 `aml_agent/client.py`）：

- **模型与端点配置**：
  - 默认模型指定为 `deepseek-flash`；
  - 支持通过环境变量注入：`DEEPSEEK_API_KEY`（或兼容 `OPENAI_API_KEY`）、`DEEPSEEK_BASE_URL`（默认可指向 DeepSeek 官方或平台兼容端点）；
  - 采样温度 `temperature` 建议固定为 `0.1`（保证规划与结构稳定）。
- **健壮性与流控**：
  - 实现网络超时与 429 限流重试（指数退避，上限 3 次）；
  - 遵循 `Callable[[str], str]` 签名，使 PlannerAgent 无感调用。
- **度量采集（Telemetry）**：
  - 在客户端或调用外层记录：单步 Prompt Tokens、Completion Tokens、调用耗时（Latency）；
  - 支持将度量指标挂载到调用轨迹（Trajectory）中，为后续消融实验储备基线数据。

### 目标 B：提示词与输出解析鲁棒性强化（满足 1.3 要求）

针对 `deepseek-flash` 等高速模型的输出特点，强化格式鲁棒性：

- 确保动作解析器能够稳定剥离 `json `、``` 包裹及思维链或说明性前言/后记，精准提取最外层的 JSON 动作对象；
- 若出现 JSON 语法残缺或不可恢复的格式错误，生成标准化的语法错误文本，供 `HardVerifier` / 反思机制触发下一轮纠错，不得直接崩溃。

### 目标 C：编写端到端冒烟与基线统计评测脚本（满足 1.2 与 1.4 要求）

在 `scripts/` 下新建或完善两个层级的运行脚本：

1. **单样本冒烟脚本**（如 `scripts/smoke_deepseek.py`）：
   - 配置一个典型的跨链场景（如 `scale_tier="Whale"`, 跨链跳跃, 目标洗钱估值 `2,000,000` USD）；
   - 执行单次完整决策循环；
   - 实时打印每一步的：Agent 动作决策、是否命中 RAG 原型、Verifier 拦截/反思日志、单步耗时与 Token；
   - 生成后导出 `smoke_graph.json`，运行纯净度审计并输出 `strategy_narrative`。

2. **小规模基线评测脚本**（如 `scripts/benchmark_phase1.py`）：
   - 按照计划书 1.2 规范，配置 3 个典型场景（如：Retail-单链分散、Whale-跨链混币、Medium-剥皮分流）；
   - 支持批量运行（如每个场景跑 3~5 条轨迹），自动统计并输出汇总报告：
     - **拓扑合法率与成功率**（`success=True` 占比）；
     - **守恒门禁初次遵循率 vs 反思后修复率**；
     - **平均步数、平均重试次数（验证是否满足 $< 0.5$ 次验收线）**；
     - **平均 Token 成本与单步延迟（Latency）**。

## 4. 铁律与交付验收指标

1. **绝对恪守零微观数值噪声**：
   - 无论提示词还是模型输出，严格杜绝真实钱包地址（`0x...`）、具体代币单位（如 `ETH`/`USDT`）、Gas 费与时间戳；
   - 导出的图元数据通过 `audit_export_purity()` 检验。
2. **测试零回归**：
   - 既有的 97 个测试（含守恒穿透套件）必须全数保持 PASS，离线 Mock 测试不得受外部 API 依赖影响。
3. **交付产物**：
   - 适配器代码、解析强化代码、冒烟与基线脚本；
   - 提供包含命令行参数说明的运行指南（例如如何配置 API KEY、如何指定并发或轨迹数）。
