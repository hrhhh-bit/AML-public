# 任务书：阶段 3（Part A）预训练 Dense 嵌入升级与双轨分层检索重构

## 1. 上下文与当前状态

系统已圆满收敛“阶段 2：真实数据蒸馏与经验性检验”。基于 `deepseek-flash` 驱动的蒸馏管线成功合并入库 6 个实战 Motif（VF2 算法成功拦截 1 个同构变体），Nomad 跨源一致性攻坚达到 **`0.6667`**（远超 $\ge 0.50$ 预定线），且全仓库 **123 个单元测试全量保持全绿**。

依据系统总体演进规划，系统现正式进入 **阶段 3：知识库批量扩容与真实 Embedding**。
本阶段（Part A）的核心任务是：攻克检索器在语义理解层面的泛化瓶颈，**将双轨检索中的语义轨由离散词法/哈希基线无缝升级为预训练稠密向量（Dense Embedding）**，并在生产知识库扩容前建立严谨的学术对比评测基准，为后续 50+ 规模知识库的精准检索奠定基座。

## 3. 核心目标与自主设计要求

### 目标 A：抽象嵌入提供者契约与多实现解耦（Pluggable Embedding Providers）

在 `aml_rag/` 模块下自主设计并实现可插拔的向量嵌入能力架构，要求满足：

- **统一抽象契约**：
  - 定义统一、面向对象的嵌入接口规范，涵盖单条查询嵌入、批量文本嵌入与向量相似度计算能力；
  - 具备轻量内存缓存意识，避免在单次规划生命周期中对相同文本重复触发高开销计算。
- **双模态 Provider 自主推导**：
  - **稠密向量 Provider（Dense Provider）**：负责接入轻量级开源预训练模型（如 `bge-small-en-v1.5` 或 `all-MiniLM-L6-v2` 等轻量开源模型），实现基于高维向量空间的高精度余弦语义计算；
  - **离散词法 Provider（Discrete Provider）**：完整封装既有的离散词法/哈希基线逻辑，作为对照组基准以及资源受限场景下的保底选项。
- **环境友好与防御性降级**：
  - 严禁硬编码任何外部商业收费 API Key；
  - 针对无外网或无 GPU 的纯 CPU / CI 运行环境，提供快速自洽的轻量运行支持或 Mock 机制，确保本地单测在毫秒级内完成。

### 目标 B：双轨分层检索管线平滑升级（Two-Stage Hierarchical Retrieval）

对现存检索器进行面向对象的依赖注入重构，满足：

- **分层检索与打分融合**：
  - 语义轨无缝挂载目标 A 抽象出的嵌入提供者，保持核心打分公式的物理意义不变：$\text{Score} = \alpha \cdot \text{Sim}_{\text{dense}} + (1 - \alpha) \cdot \text{RuleSat}$；
  - 严格保持前沿状态拓扑硬门禁（可达角色、出度饱和、体量等级匹配等）的有效性，确保“粗排（稠密语义初筛）$\to$ 精排（图结构硬门禁与融合加权）”的两阶段机制自洽运转。
- **零破坏性重构（Zero-Breaking Change）**：
  - 重构后必须对上游规划 Agent 完全无感，严禁改动已通过全量测试的既有调用接口规范。

### 目标 C：构建密集检索 vs. 离散基线量化排序评测体系

设计并实现一套可复现的学术对比实验套件，采集稠密嵌入相对离散基线的量化改进证据：

- **测试执行脚本规范**：
  - 在 `scripts/` 目录下创建独立的评测执行脚本（如 `scripts/eval_retrieval_correlation.py`）；
  - 设定多组覆盖不同反洗钱语义（如跨链跳板、大额分流拆分、DEX 兑换混淆等）的典型测试场景 Query。
- **学术度量指标与实验归档**：
  - 针对当前物理知识库中的实战 Motif，分别采集 Dense 模式与 Discrete 模式下的候选图排序结果；
  - 计算两组排序的 **Spearman 等级相关系数（Spearman's $\rho$ 与 $p$-value）**，量化评估密集语义对近义意图识别的重排序敏感度与区分效力；
  - **实验产物落位要求**：将生成的量化分析报告（包含详细的 Query 对比数据、统计指标与摘要）以格式化 JSON 文件保存至指定的实验资产目录：`experiments/phase3_dense_retrieval/`，并在控制台打印易读的汇总表格。

## 4. 铁律红线与交付验收标准

1. **Stage-1 抽象红线与评测解耦**：
   - 稠密向量的嵌入文本对象绝对严禁引入真实钱包地址、代币符号、微观金额、Gas 费或时间戳；
   - 评测运行过程属于**只读只度量流**，绝对严禁隐式修改或污染生产知识库物理资产（`distilled_kb.json`）。
2. **工程与单测验收线**：
   - 全仓库既有 **123 项单元测试必须 100% 持续保持全绿**（Zero Regression）；
   - 新增针对 Embedding 抽象接口、各 Provider 实现及检索器升级的完备单元测试，全套单测数量实现正向净增长；
   - 真实端点冒烟脚本（`python scripts/smoke_deepseek.py`）复测通过，证明在真实 LLM 决策闭环中稠密检索的前置注入行为完全自洽。
3. **目录规范与交付物**：
   - 核心代码沉淀于 `src/aml_rag/`；
   - 单元测试沉淀于 `tests/`；
   - 评测执行脚本落位于 `scripts/`；
   - 实验评测结果文件落位于 `experiments/phase3_dense_retrieval/`。
