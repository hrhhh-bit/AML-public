# 任务指引：研报采集子系统信噪比重构、多源负向过滤与深度资金流增补流水线 (v2)

## 1. 角色定位与设计哲学

你是一名资深实证数据管线架构师兼区块链反洗钱系统专家。
在第一轮研报采集（Identification）与实证审查中，我们发现了影响后续拓扑蒸馏的三项系统性噪音：

1. **CertiK 域名规则穿透**：因 `kind="page"` 误抓了大量商业产品/代码审计页面（如 _Smart Contract Audit_, _KYC Verification_）；
2. **BlockSec 追踪断档**：受限于 Medium RSS 最近 10 篇的截断，抓取的全为纯代码脆弱点分析（0 跳后置资金轨迹）；
3. **宏观合规与社工通报噪音（含 SlowMist）**：抓取到了如 _FATF Report_（宏观合规政策解读）、_Job-Seeking Phishing_（社工钓鱼通报）等无链上资金转移图的泛安全研报。

当前任务是对 `tools/crawler/` 采集子系统进行**“多维度负向清洗与定向高保真拓扑增补”**，在保留存量真实黑客追踪长文的前提下，剔除产品页与宏观合规通报，激活开源深度事故库，重构一份规模在 60~80 篇、高信噪比的黄金研报池。

## 2. 物理目录隔离与历史备份红线（Hard Tenets）

- **目录隔离铁律**：所有修改严格限定在 `tools/crawler/` 与 `tests/test_crawler.py`；
- **防污染铁律**：严禁导入 `src/` 中的任何推理模块，**绝对严禁读写或修改**生产物理知识库 `data/distilled_kb.json`；
- **历史资产备份防线**：在执行任何清洗或覆盖前，脚本必须首先将现有的 `data/raw_reports/` 完整备份至 `data/raw_reports_v1_backup/`，严禁直接物理抹除旧数据。

## 3. 核心改进要求与采集策略调整

### A. 存量资产归档与精细化剪枝（Surgical Pruning）

1. 自动备份现存 `data/raw_reports/` 至 `data/raw_reports_v1_backup/`；
2. 读取现有 `manifest.csv`，基于 URL/标题特征执行**负向黑名单硬淘汰**，彻底剔除以下两类噪声文件：
   - **商业/审计废纸**：标题或 URL 包含 `smart-contract-audit`、`kyc`、`penetration-testing`、`bug-bounty` 等；
   - **宏观政策与社工报告**：标题包含 `FATF`、`Regulatory`、`Compliance Guide`、`Phishing`、`Job-Seeking`、`Policy` 等无链上流向的文章；
3. 保留真正聚焦于“事件（Incident）、黑客（Hacked）、攻击（Exploit）、资金追踪（Tracing/MistTrack）”的报告。

### B. 爬虫调度器引入“全局负向主题词硬拦截”（Global Negative Filters）

- 在 `tools/crawler/` 的过滤漏斗中增加标题与正文关键词的负向排除名单：
  `NEGATIVE_KEYWORDS = ["FATF", "compliance guideline", "job-seeking", "recruitment phishing", "audit report summary", "kyc verification"]`
- 即使命中 AML 关键词，只要标题显著落入上述负向区间，一律直接抛弃，不落盘。

### C. CertiK 采集规则修补（Incident Focus）

- 修改 `tools/crawler/vendor_registry.py` 中 CertiK 页面发现规则；
- 剔除对裸域名 `certik` 字符串的宽松匹配；
- 约束抓取链接必须匹配包含：`/resources/blog/incident-analysis/`、`/resources/blog/hack/`、`/resources/blog/security-incident/` 等真实黑客攻击专题路径。

### D. 激活开源深度事故追踪库（解决 BlockSec 与链上资金流短板）

- 深度激活对 `SunWeb3Sec/DeFiHackLabs` 及相关开源安全事故复盘归档库的爬取；
- 重点检索并抓取带有 `Phalcon`、`BlockSec`、`Fund Flow`、`Money Tracing`、`Tornado`、`Cross-chain` 标签的历史 Markdown 归档；
- 此类归档原生自带清晰的链上转移多跳说明或 ASCII 资金流图，专门填补 BlockSec 的洗钱拓扑空白。

### E. 配额自适应重平衡与 Manifest 维护

- 重新设定分层配额：**四大厂商高信噪比研报各保底 15~20 篇，总目标规模 60~80 篇**；
- 维护 `data/raw_reports/manifest.csv`，确保 `report_id` 自增连续，格式符合 RFC 4180，`has_fund_flow` 列重置为空字符串 `""` 留待专家最终核验。

## 4. 自动化测试规范（tests/test_crawler.py）

更新并扩充 `tests/test_crawler.py`（离线 Mock 测试）：

1. **负向关键词拦截测试**：构造含 `FATF`、`Job-Seeking Phishing` 的 Mock 标题，验证调度器能 100% 自动丢弃；
2. **CertiK 路径精准过滤测试**：验证能准确拦截商业页并放行真实 Incident 链接；
3. **DeFiHackLabs 资金流归档解析测试**：验证 Markdown 格式事故复盘与 ASCII 链路的抽取完备性；
4. **单测基线红线**：原有的 237 项全量单测必须保持 100% 通过（0 regressions）。

## 5. 验收交付物与汇报要求

执行采集后，Agent 必须在交付报告中详细回答：

1. **本次采集的核心目标与配额达成情况**（各大厂商最终保留与新增数量、平均字数）；
2. **针对性策略阐释**：
   - 负向过滤规则剔除了多少篇合规/社工/商业噪音；
   - 如何通过 DeFiHackLabs / Phalcon 专题补齐了 BlockSec 的链上多跳资金流研报；
3. **最终 `manifest.csv` 的信噪比预估**与下一步定标建议。

# 任务指引：构建 PRISMA 资格准入自动化辅助核验流水线 (scripts/screen_manifest.py)

## 1. 角色与目标

你是一名区块链安全研究员兼实证数据工程师。
当前任务是为已采集的 56 篇研报（记录于 `data/raw_reports/manifest.csv`）开发一个自动化的资格准入核验脚本 `scripts/screen_manifest.py`。
该脚本负责批量判定每篇研报是否包含合格的链上资金洗钱/转移轨迹（≥ 2 跳），自动填充 `manifest.csv` 中的 `has_fund_flow` 列（`1` 或 `0`），并伴生输出结构化的评审证据台账。

## 2. 判定硬门禁（严格遵守）

- **合格 (打标 1)**：正文中明确包含黑客/洗钱者获利后的**后置链上资金轨迹（≥ 2 跳）**（包含单链内的 TRANSFER、SWAP、SPLIT、MERGE、进混币器，或跨链 BRIDGE）。
- **排除 (打标 0)**：纯代码漏洞原理剖析（资金仅停留在初始获利地址无变动）、宏观合规政策、社工钓鱼案例。

## 3. 功能与工程要求

1. **输入与调度**：
   - 逐行读取 `data/raw_reports/manifest.csv`；
   - 根据 `filename` 读取对应 `data/raw_reports/*.txt` 正文；
   - 充分复用已有的 `tools/crawler/` 中的 `analyze_fund_flow_evidence` 正则证据（已有 36 篇检出标记）结合 LLM 判断，或直接调用项目既有的 LLM API Client；
2. **两阶段安全写回**：
   - 更新 `data/raw_reports/manifest.csv` 的 `has_fund_flow` 列（更新为 `1` 或 `0`）；
   - 写回必须满足 RFC 4180 规范，保留原表头和已有字段；
3. **学术证据伴生审计（Audit Trail）**：
   - 同步输出 `data/raw_reports/eligibility_audit.json`，格式如下：
     ```json
     {
       "rep_blocksec_001": {
         "has_fund_flow": 1,
         "hops_detected": 3,
         "evidence_chain": "Exploiter -> Intermediate 0x.. -> Uniswap Swap -> Tornado.Cash",
         "reason": "包含完整获利后兑换与混币链条，满足 I1 准入规则"
       }
     }
     ```
4. **控制台汇总汇报**：
   - 执行完毕后在控制台打印各大厂商的判定分布表（例如：BlockSec 12/15 合格，SlowMist 5/7 合格，总计合格 XX 篇）。

## 4. 验收指标

- 运行 `python scripts/screen_manifest.py`（支持 `--dry-run` 离线使用已有的 regex/heuristic 证据，或支持调用 LLM 完成判定）；
- `manifest.csv` 中 56 条记录的 `has_fund_flow` 列全部被正确填充为 `0` 或 `1`，无空字符串；
- `eligibility_audit.json` 完整记录 56 篇研报的判定理由，证据链清晰。
