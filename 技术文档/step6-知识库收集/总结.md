# 研报采集与资格筛选流程总结

本文档回顾本项目研报数据池从"第一版粗放采集"到"第二版信噪比重构"，再到"PRISMA 资格准入筛选"的完整演进过程，涵盖两版采集策略的差异、最终筛选规则、人工复核结果以及面向同行评审的方法论答辩支撑。

## 一、第一版：以正向关键词匹配为主的粗放式采集

第一版采集（成果现完整保留于 `data/raw_reports_v1_backup/`，共 74 篇）围绕 SlowMist、BlockSec、PeckShield、CertiK 四大安全厂商展开，数据来源是各家 Medium 官方 RSS、官网博客列表页以及 SlowMist 的 GitHub Knowledge-Base 仓库。检索采用"统一 AML 词表 + 厂商专属词"叠加的方式：统一词表覆盖 AML、anti-money laundering、money laundering、laundering、fund flow、fund tracing、资金追踪、洗钱、洗币等主题词，厂商专属词则包括慢雾、phishing、fund tracking（SlowMist）、post-mortem、attack、exploit（BlockSec）、incident、hack（PeckShield）以及 skynet、incident、audit、exploit（CertiK）。入池标准本质上只有一道正向门禁——只要标题或正文命中上述任一关键词、正文长度落在 500 至 50000 字符之间即可落盘，链接发现阶段甚至允许以"URL 中出现厂商裸域名"（例如包含 `certik` 字样）作为放行条件。这种只放行不拦截的策略带来了明显的信噪比问题：最终 74 篇中 CertiK 一家就占了 40 篇，其中混入了大量官网首页、certik-report 仪表盘、blog 索引页与 Policy Pulse 等政策文；BlockSec 池里挤满了 Phalcon 产品公告类内容；SlowMist 池则收录了 FATF 政策报告、求职钓鱼通报等非事件文。真正符合"黑客攻击 + 链上资金流转"主题的高质量研报被淹没在噪音之中。

## 二、第二版：信噪比重构、多源补源与分层配额

第二版针对第一版的缺陷做了系统性的策略修补，核心思路是"负向拦截 + 精准路径 + 开源事故库补源 + 分层配额"四管齐下。在动手清洗之前，流水线先把第一版 74 篇研报完整备份至 `data/raw_reports_v1_backup/`，形成历史资产防线。随后引入两层负向过滤：运行时层面新增全局负向主题词硬拦截名单（FATF、compliance guideline、job-seeking、recruitment phishing、audit report summary、kyc verification 等），标题命中即在发起 HTTP 抓取之前直接抛弃，正文命中则在提取后抛弃，多轮采集累计拦截 400 余次；存量层面建立标题与 URL 剪枝黑名单（正则特征库），对商业审计页、产品导航页、宏观政策文、社工通报文做硬淘汰，并分三轮执行精细剪枝——74 篇先剪至 25 篇，再经 57 篇剪至 41 篇，最后 72 篇剪至 41 篇。链路发现规则同样收紧：CertiK 只放行 `/resources/blog/incident-analysis/`、`/resources/blog/hack/`、`/resources/blog/security-incident/` 等事故专题路径，彻底废除裸域名 `certik` 宽松匹配，其 Medium 源再叠加 incident、hack、exploit、attack 事件词标题白名单。为了补足 BlockSec 与 PeckShield 的链上资金流内容短板，流水线激活了两个开源深度事故库——BlockSec 由 SunWeb3Sec/DeFiHackLabs 仓库按 Phalcon、BlockSec、Fund Flow、Money Tracing、Tornado、Cross-chain 等资金流标签定向取档（GitHub 树 API 被限流时自动回退 codeload tarball 整仓归档解析），PeckShield 由 Rivaill/CryptoVulhub 仓库补入真实 DeFi 黑客事故复盘；此外 BlockSec 官网博客的三篇 Exploit 事故分析与 USDT Freeze Tracker 资金冻结追踪文也纳入采集。采集规模则改为"总目标驱动 + 分层配额"调度：全局目标 60~80 篇，单厂商保底 15 篇、软上限 20 篇（跨轮累计防垄断），未达标厂商最多补扫两遍。经过这一系列改造，最终形成 56 篇高信噪比事件研报池（SlowMist 7 篇、BlockSec 15 篇、PeckShield 20 篇、CertiK 14 篇），池内全部为事件、攻击或资金追踪主题，36 篇正文检出链上资金流标记或 ASCII 多跳链路，台账统一为 RFC 4180 格式并重排了连续的 report_id。

## 三、最终筛选：PRISMA 资格准入与双层判定

在 56 篇事件研报池成型后，`scripts/screen_manifest.py` 按 PRISMA 资格准入框架执行最终定标。硬门禁只有一条：正文必须明确呈现黑客或洗钱者"获利之后"不少于 2 跳的链上资金轨迹，包括单链内的 TRANSFER、SWAP、SPLIT、MERGE、进混币器，或跨链 BRIDGE；纯漏洞原理剖析（资金停留在初始获利地址不动）、宏观合规文、社工钓鱼文与产品页一律排除，攻击执行步骤（闪电贷、攻击合约调用等）也不计入跳数。判定采用双层引擎双保险：Tier-1 是一套高精度资金轨迹事件正则（对转移、兑换、跨链、拆分、聚合、混币器等动作逐一匹配，并针对"获利资金分布拆分"这类正则盲区做了专门规则），逐篇可复现；Tier-2 是 LLM 语义通读终审，将每篇正文（前 35000 字符）交给 DeepSeek 系模型按结构化 JSON 契约判定，单篇失败时自动回退启发式。判定结果通过两阶段安全写回落地：`manifest.csv` 的 `has_fund_flow` 列全量回填 0/1，同时伴生输出 `data/raw_reports/eligibility_audit.json` 证据台账，56 条记录逐篇保留跳数、证据链片段、判定理由与引擎来源。

## 四、人工复核与最终成果

初筛程序初步产出 17 篇候选（含 2 篇由启发式正则打捞入池的篇目）。为确保下游拓扑蒸馏具备 100% 的因果真实性，避免模型脑补交易边，研究人员对 17 篇候选逐一执行了代码级人工交叉复查（Human-in-the-loop），精准识别并排除了 **3 篇因果假阳性（False Positives）**：

1. **`rep_certik_009` (Gyroscope 案)**：其 Arbitrum $\to$ Ethereum 跨链桥接仅为黑客传递 1 wei 任意 calldata 的漏洞触发载荷（PRISMA E1）；获利后的真实洗钱部分仅有一笔存入 300.2 ETH 至 Tornado Cash，实质仅构成 1 跳存款，缺乏多跳清洗拓扑，判定改标为 0（`llm_verified_exclusion`）。
2. **`rep_certik_006` (Resolv Protocol 案)**：全文仅列出黑客控制的 3 个地址持有 wstUSR 与 ETH 的**静态持币快照（Balance Snapshot）**。尽管现实中存在兑换与分流，但原文未记录任何显式有向交易边（$u \to v$），若纳入将迫使下游 LLM 违规脑补交易边，依据 PRISMA E3 剔除并改标为 0（`llm_verified_exclusion`）。
3. **`rep_blocksec_008` (Nostra 周报案)**：提取出的链路中，`paid to the block builder` 实质是以太坊出块节点的 MEV 贿赂款，`exchanged PAT for aEth` 属于攻击合约内部的抵押兑换逻辑，通篇缺失获利后外部钱包的独立洗钱 DAG，依据 PRISMA E1 剔除并改标为 0（`llm_verified_exclusion`）。

由此，数据池最终收敛确定为 **14 篇“物理级纯净（100% 具备 $\ge 2$ 跳显式后置交易边）”的黄金定标集**：

- **SlowMist (2 篇)**：`rep_slowmist_001`（Liquid Network 缓存碰撞）、`rep_slowmist_002`（FomoPeek 投毒，含 10 跳超复杂跨链分流拓扑）；
- **BlockSec (1 篇)**：`rep_blocksec_009`（Symbiosis 案，从周报中剥离出清晰的 DEX Swap 及 ETH 中继流转）；
- **CertiK (11 篇)**：`rep_certik_001`（Liquid Network）、`rep_certik_002`（Verus）、`rep_certik_003`（DefiTuna）、`rep_certik_004`（JaredFromSubway MEV，含 4 跳分流与 Tornado 洗钱）、`rep_certik_005`（GnosisPay）、`rep_certik_007`（Movie Token）、`rep_certik_008`（SOF/LAXO）、`rep_certik_010`（Truebit）、`rep_certik_011`（Balancer）、`rep_certik_012`（Cyrus Finance）、`rep_certik_013`（Evil in the Shadows）；
- **PeckShield (0 篇)**：全量排除。

至此，`data/raw_reports/` 中 56 篇研报的 `has_fund_flow` 列无空值、台账与正文严格一一对应。最终 14 篇构成供下游 Stage-1 拓扑蒸馏的高质量黄金输入集，其余 42 篇判定为 0 的文章完整保留作为负向对照。
