# 任务指引：构建独立的数据采集子系统与四厂商分层研报爬取流水线

## 1. 角色定位与设计哲学

你是一名资深分布式爬虫与实证数据管线架构师。
当前任务是为跨链 AML 拓扑生成系统（Stage-1）构建一个**完全物理解耦的原始研报采集子系统**。
系统必须严格遵循实证学术规范（PRISMA 数据漏斗标准），通过**“分层配额采集（Stratified Harvesting）”**机制，均衡自动化抓取来自 **慢雾 (SlowMist)、派盾 (PeckShield)、BlockSec、CertiK** 四大权威厂商的反洗钱与黑客资金追踪研报，建立可追溯的研报文本库与元数据台账。

## 2. 物理目录隔离与架构边界红线（Hard Isolation Tenets）

为了确保数据采集与核心推理/蒸馏引擎彻底解耦，必须严格遵守以下目录规范：

- **独立工具包目录**：所有采集相关代码、依赖与配置文件必须存放在新目录 `tools/crawler/` 中：
  - `tools/crawler/crawl_reports.py`：主采集入口与调度器；
  - `tools/crawler/vendor_registry.py`（或 `sources.json`）：四大厂商数据源配置、检索词与配额定义；
  - `tools/crawler/extractor.py`：正文抽取与清洗封装（优先集成 `trafilatura`，辅以回退策略）；
- **数据输出唯一目标**：所有抓取产物仅允许输出至：
  - 研报文本落盘：`data/raw_reports/{report_id}_{date_or_slug}.txt`；
  - 元数据总账：`data/raw_reports/manifest.csv`；
- **架构隔离红线（Strict Isolation）**：
  - `tools/crawler/` 下的代码**严禁**导入 `src/` 中的任何状态机、RAG 向量检索或 Agent 决策模块；
  - 采集脚本**绝对严禁读写或修改**生产物理知识库 `data/distilled_kb.json`。

## 3. 核心功能与技术要求

### A. 四大厂商分层配额控制（Stratified Quota Control）

- 数据源必须均衡覆盖四大核心安全厂商：
  1. **SlowMist**（慢雾官方 GitHub 归档库 / Medium / 博客 RSS）
  2. **BlockSec**（BlockSec 官网 Blog / Medium 技术专栏）
  3. **PeckShield**（PeckShield Medium / 权威事故归档）
  4. **CertiK**（CertiK Resources Incident Reports / Medium）
  - _(学术快捷源说明：支持通过公开事故分析聚合归档如 `SunWeb3Sec/DeFiHackLabs` 按参考来源标签直接索引上述厂商的 incident post-mortems)_
- **配额管理**：支持配置每个厂商的目标采集量（如每家保底 15~25 篇，总目标规模 60~100 篇），单厂商满额后自动停止该厂商检索，杜绝单一信源垄断。

### B. 高保真正文提取与降噪（DOM Stripping）

- 采用健壮的 HTTP 请求机制（配置合理的 User-Agent、超时重试与速率限制，防范反爬封锁）；
- 集成 `trafilatura` 执行高保真纯文本提取，自动剥离网页 Header、Footer、导航栏、侧边推荐及广告；
- 字符数准入过滤：提取后纯文本有效长度必须在 `[500, 50000]` 字符区间，剔除空页面或抓取失败的碎片页面。

### C. 统一元数据资产台账（PRISMA Manifest.csv）

每成功采集并持久化一篇研报，必须使用 RFC 4180 标准以 UTF-8 编码同步登记至 `resources/raw_reports/manifest.csv`。表头规范严格定义如下：

- `report_id`：全局唯一自增编号（格式：`rep_{vendor_code}_{index:03d}`，如 `rep_slowmist_001`）；
- `vendor`：厂商名称枚举（`SlowMist` / `BlockSec` / `PeckShield` / `CertiK`）；
- `title`：研报原始标题；
- `publish_date`：发布时间（格式 `YYYY-MM-DD`，未知可留空）；
- `matched_kw`：命中的检索关键词（如 `AML, 洗钱, money laundering, fund flow`）；
- `url`：原始来源永久链接；
- `filename`：保存在 `data/raw_reports/` 的相对文件名；
- `has_fund_flow`：人工审核标记列（初始化为空字符串 `""`，留待后续人类专家定标）。

### D. 控制台健康度仪表盘（Console Telemetry）

采集过程中及结束时，脚本必须在控制台打印结构化健康度汇总表，展示各厂商成功采集量、有效字数均值、配额达成率与错误/跳过统计。

## 4. 自动化测试规范（tests/test_crawler.py）

必须在 `tests/test_crawler.py` 中编写离线测试套件（使用 `unittest.mock` 模拟 HTTP 响应，杜绝单测发起真实外网请求）：

1. **厂商配额均衡测试**：验证调度器在达到单个厂商 Quota 限制时能正确分流/熔断；
2. **正文提取与降噪测试**：Mock 包含网页广告与噪声标签的 HTML 片段，验证提取器能准确抽取出纯净主体；
3. **Manifest 幂等性与增量写入测试**：验证重复抓取同一 URL 或已有报告时具备去重跳过能力，且 CSV 追加操作格式完全合规；
4. **物理隔离防御测试**：验证脚本执行不触碰 `data/distilled_kb.json`。

## 5. 验收准出阈值

1. 新增的 `tests/test_crawler.py` 必须全部通过，且系统存量的 216 项单测保持 100% 通过（Total Tests $\ge 222+$）；
2. 执行 `python tools/crawler/crawl_reports.py --dry-run` 或配置小型 Mock 源能够平稳跑通全流程；
3. 生成的 `data/raw_reports/manifest.csv` 符合预定 Schema，字段与实际落盘的 `.txt` 文本严格一一对应。
